# KR&BR — قاعدة بيانات MySQL + تشفير وحماية

تم إنشاء قاعدة بيانات **MySQL** للمشروع تتكوّن من **جدول واحد** (`users`) يحفظ
كل بيانات حسابات البائعين والمشترين (والمدير) **وبيانات بطاقاتهم البنكية في نفس
الجدول**، وتم ربطها بالواجهة الأمامية عبر Flask، مع رفع مستوى التشفير والحماية.

---

## 1) المتطلبات
- **MySQL Server** مُثبّت ويعمل (لم يكن مُثبّتاً على هذا الجهاز، لذا يجب تثبيته أولاً).
  - على Windows: نزّل MySQL Community Server من mysql.com، أو استخدم XAMPP.
- **Python 3.11+** (موجود: 3.13).
- الاعتماديات في `requirements.txt` (تم تثبيتها بالفعل على هذا الجهاز).

## 2) خطوات التشغيل
من مجلد المشروع (`d:\KR&BR`):

```powershell
# (تُثبّت مرة واحدة فقط)
python -m pip install -r kr-br/backend/requirements.txt
```

### أ) اضبط بيانات MySQL
افتح `kr-br/backend/.env` واكتب كلمة مرور MySQL الحقيقية:
```
MYSQL_USER=root
MYSQL_PASSWORD=اكتب_كلمة_مرور_MySQL_هنا
```
> مفاتيح التشفير (`AES_KEY`, `CARD_HMAC_KEY`, `FLASK_SECRET_KEY`) تم توليدها
> تلقائياً داخل `.env`. لا تشاركها ولا ترفعها إلى Git (ملف `.env` مُستثنى عبر `.gitignore`).

### ب) أنشئ القاعدة والجدول وحساب المدير
```powershell
python kr-br/backend/setup.py
```
ينشئ: قاعدة البيانات `kr_br` + الجدول `users` (جدول واحد) + حساب المدير،
ويطبع بيانات دخول المدير.

### ج) شغّل الباك إند
```powershell
python kr-br/backend/server.py
```
سيعمل على `http://127.0.0.1:5000`.

### د) افتح الموقع
الأفضل فتحه من نفس خادم الباك إند (نفس الأصل، لا مشاكل CORS):
```
http://127.0.0.1:5000/
```
أو افتح `kr-br/index.html` مباشرة في المتصفح (CORS مُفعّل فيحصل الاتصال بـ `127.0.0.1:5000`).

## 3) بيانات المدير
- البريد الافتراضي: `admin@krbr.com`
- كلمة المرور: ما يطبعها `setup.py` (أو عيّنها عبر `ADMIN_PASSWORD` في `.env`).
- الدخول بحساب المدير يحوّلك تلقائياً إلى `admin.html`.

---

## الجدول الواحد (`users`)
كل بيانات الحسابات + البطاقة في صف واحد لكل مستخدم:

| المجموعة | الأعمدة |
|---|---|
| الهوية | `id`, `name`, `email`, `password_hash`, `account_type`, `balance` |
| الحماية | `status`, `failed_login_attempts`, `locked_until`, `last_login_at`, `last_login_ip` |
| البطاقة (مشفّرة) | `card_number_enc`, `card_number_hmac`, `card_last4`, `card_brand`, `card_expiry_enc`, `card_cvv_enc`, `card_holder_enc`, `card_updated_at` |
| التدقيق | `created_at`, `updated_at` |

`account_type` ∈ (`buyer`, `seller`, `admin`) — البائع والمشتري والمدير في نفس الجدول.

## 4) مستوى التشفير والحماية المرفوع
- **كلمات المرور**: `bcrypt` (salt مدمج، cost 12) بدلاً من `sha256` وبدلاً من `btoa` في الواجهة.
- **بيانات البطاقة**: تشفير **AES-256-GCM** (مصادَق) لكل من: رقم البطاقة، تاريخ الانتهاء، الـCVV، اسم الحامل — مخزّنة كنصوص مشفّرة فقط. لا يُخزَّن نص واضح أبداً.
- **رقم البطاقة**: يُخزَّن كذلك بصيغة **HMAC-SHA256** (لا رجعة فيه) للبحث عن التكرار دون فك التشفير، + آخر 4 أرقام للعرض المقنّع فقط.
- **الجلسات**: **توكن موقّع بـ HMAC** (بدلاً من الاعتماد على localStorage أو كلمة مرور المدير المكتوبة في الكود). كل طلب محمي يرسل `X-Auth-Token`.
- **مقاومة الاختراق بالتخمين**: تحديد معدّل المحاولات لكل IP + قفل الحساب تلقائياً بعد 5 محاولات فاشلة لمدة 15 دقيقة + إخفاء هل البريد موجود (ردّ موحّد).
- **الاستعلامات**: كلها **parameterised** (لا SQL injection عبر الإدخال).
- **التحقق من البطاقة**: تحقق رقم البطاقة (Luhn) + كشف نوعها + منع ربط البطاقة بحسابين.
- **الإخراج**: لا يُعاد أبداً `password_hash` ولا النص المشفّر ولا الرقم الكامل للعميل — يُعاد رقم مقنّع (`**** **** **** 4242`) فقط.
- **الترويسات الأمنية**: `X-Content-Type-Options`, `X-Frame-Options`, `Referrer-Policy`, `Cache-Control: no-store`.
- **الأسرار**: كلها من `.env` (لا شيء مكتوب في الكود)، وملف `.env` مُستثنى من Git.

## 5) ما الذي تغيّر في الواجهة
- `app.js`: التسجيل/الدخول أصبحا يستدعيان الـ API (`/api/register`, `/api/login`) بدل localStorage، وتم حذف كلمة مرور المدير المكتوبة في الكود، ولم تعد كلمة المرور تُخزَّن في المتصفح.
- `dashboard.js`: ربط الفيزا يحفظها مشفّرة في MySQL؛ العرض مقنّع، ولا يُملأ الرقم الكامل في الحقل.
- `admin.js`: جدول المستخدمين يُجلب من MySQL؛ حذف مستخدم وحفظ فيزا المدير عبر الـ API.

> ملاحظة PCI DSS: تخزين CVV بعد التفويض غير مسموح في أنظمة الدفع الحقيقية.
> تم تشفيره هنا فقط لإكمال واجهة العرض. في الإنتاج احذف عمود `card_cvv_enc`.

## 6) الملفات
```
kr-br/backend/
  schema.sql        # إنشاء قاعدة البيانات + الجدول الواحد
  security.py       # التشفير (AES-256-GCM / bcrypt / HMAC) + التوكنات + تحديد المعدل
  server.py         # Flask API (MySQL) + الحماية
  setup.py          # توليد المفاتيح + إنشاء القاعدة والجدول + حساب المدير
  requirements.txt  # الاعتماديات
  .env / .env.example   # الإعدادات والأسرار (لا ترفع .env)
  .gitignore        # يستثني .env و __pycache__ و *.db
```
